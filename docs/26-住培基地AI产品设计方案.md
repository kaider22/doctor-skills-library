# 住培基地AI业务 · 产品设计方案

> **设计时间：** 2026-10-19
> **定位：** 面向住院医师规范化培训基地的 AI OSCE 模拟训练 + AI 考官自动评分系统
> **铁律：** 不向医生、患者、医院科室（临床）收费；商业价值来自企业侧（药企/器械/商保）与教学机构B端
> **前置调研：** docs/25《AI医学教育方向深度调研》+ 浙江49家国家级住培基地清单

---

## 〇、一句话定位

**给住培基地一套"AI虚拟标准化病人 + AI考官自动评分"的OSCE训练考核系统，绑定住培结业OSCE三考站，让基地低成本高频练兵、学员实时获反馈、通过率可视化。** 先攻浙江，再复制全国，最后引擎出海。

---

## 一、产品要解决的真实痛点

### 1. 住培基地教学管理部门（采购决策方）
| 痛点 | 现状 | 我们的解法 |
|------|------|-----------|
| 结业OSCE通过率是硬指标 | 但训练/考核资源不足 | AI低成本高频练兵，通过率可预测 |
| 标准化病人太贵 | 一次 $2500–5000（国内约1000–3000元/次） | AI虚拟病人，成本趋近于零 |
| 高保真模拟人太贵 | 一台 $6.5万–10万 | 软件替代，便宜一个数量级 |
| 考官人力不足 | 结业考核需大量考官 | AI考官自动评分，减轻人力 |
| 评分标准不统一 | 各基地、各考官主观差异大 | 对齐国家OSCE评分表，标准化 |

### 2. 住培学员（使用者）
- 训练机会太少：真实标准化病人约不到，OSCE练手机会稀缺
- 反馈不及时：考完很久才知道结果，不知道错在哪
- 不知道真实水平：缺乏对标全国/全基地的量化评估

### 3. 带教老师/考官
- 评分耗时耗力、主观、复盘麻烦
- 缺乏标准化的评分依据和教学过程留痕

## 二、用户角色与权限

| 角色 | 使用场景 | 核心权限 |
|------|---------|---------|
| **基地教学管理员**（采购方） | 建班、排考、看报表 | 全量管理+数据看板 |
| **带教老师/考官** | 布置训练、审核病例、复核AI评分 | 教学管理+评分复核 |
| **住培学员** | 日常训练、模拟考核、查成绩 | 训练+个人报告 |
| **药企医学部**（企业侧） | 投AI病例库、看触达/学术数据 | 数据洞察（脱敏） |

---

## 三、核心功能模块

### 模块1：AI虚拟标准化病人（AI-VSP）
- **问诊交互：** 语音+文字双通道，学员像面对真实病人一样问诊
- **体格检查：** 基于主诉引导查体选项
- **病例库：** 多专科病例，**先全科+内科**（947个全科基地是政策重点）
- **动态应变：** 病人对提问的应答基于病情逻辑，会"变脸、隐瞒、情绪化"
- **多语言：** 中文为主，预留英文（出海用）

### 模块2：AI考官自动评分
- **对齐OSCE三考站评分表**（病史采集、体格检查、临床思维/处理、医患沟通）
- **多维评分：** 沟通、采集、推理、处置、文书
- **即时反馈：** 每题/每站出分，附改进建议
- **人机复核：** AI初评 + 带教老师抽查复核（保留人的终审权）

### 模块3：教学管理后台
- 学员管理、排班、训练计划
- **成绩分析：** 通过率预测、薄弱环节诊断、个体/班级对标
- **数据看板：** 对标国家标准、基地间匿名对比

### 模块4：考核模式
- **日常训练模式：** 学员自主练习，AI即时反馈
- **模拟考核模式：** 全流程OSCE模拟，计时、多站轮转
- **结业预测：** 基于训练数据预测结业通过概率

---

## 四、业务流程

```
采购签约 → 部署开通 → 建班排程 → 学员注册
→ 日常训练（AI-VSP问诊+即时评分）
→ 模拟考核（全流程OSCE）
→ 数据分析（通过率/薄弱环节）
→ 输出报告（给基地/给药企）
→ 续费/扩展（新专科/新病例）
```

## 五、定价与商业模式

### 方案A：机构年费（住培基地B端）——推荐主收入
| 计费方式 | 定价锚点 | 单个基地年值 |
|---------|---------|------------|
| 按在培学员数 | 对标BioDigital $15/学生/年 ≈ 80–120元/人/年 | 100人基地 ≈ 1–1.2万/年 |
| 按基地整体 | 分级：三甲示范基地/市级基地 | 3–20万/年 |

**天花板测算：** 浙江49家 × 渗透10% ≈ 首年几十万；全国1114家 × 渗透10% ≈ **1.3亿/年**

### 方案B：药企学术教育赞助（企业侧，最贴铁律）
- 药企向基地投"科室AI病例库"，按科/年 50–200万
- 走"医学学术教育合作"合规协议，非广告
- 药企获得脱敏的病例训练数据与触达（非患者诊疗数据）

### 方案C：出海复制（第二曲线）
- 引擎复用，改考纲（USMLE/中东/东南亚）+ 英文
- 卖海外医学院/住培机构B端

## 六、合规与铁律辨析（关键）

> **铁律原文：** 不向任何医生和患者（含医院科室）收取任何费用，商业价值全部来自企业侧。

**这里有一个必须想清楚的边界：**
- 住培基地 = 医院的教学部门，严格说也属于"医院科室"
- 如果直接向住培基地收软件年费，理论上踩"含医院科室"红线

**两条合规路径（建议选B优先、A为辅）：**

**路径B（首选，零风险）：** 基地**免费/低价**用AI OSCE工具 → 换训练数据和基地标杆背书 → 向**药企**收学术教育赞助/病例库费。完全不碰基地口袋。

**路径A（可行但有边界）：** 若基地把AI训练当作**采购的教学服务/耗材**（非诊疗、非患者），按"医学教学服务"立项，向基地收服务费。这区别于"向医生个人/患者收费"，且不涉及临床诊疗。**建议此路径只在有药企赞助兜底时采用。**

> ⚠️ 最稳妥的组合：**基地免费换数据 + 药企付费做商业 + 出海换市场**。产品本身永远不向医生个人和患者收费。

## 七、MVP范围（3个月可交付）

**目标：** 单个试点基地跑通"训练→评分→报告→续费"闭环

| 模块 | MVP范围 |
|------|--------|
| AI-VSP | 全科+内科各20个病例，语音+文字问诊 |
| AI考官 | 对齐三考站评分表，自动评分+反馈 |
| 管理后台 | 学员管理+训练记录+基础报表 |
| 考核 | 日常训练模式 + 1次模拟考核 |

**试点对象：** 树兰（杭州）医院（民营、决策快、全科在招）

**成功指标：** 学员训练频率↑、OSCE通过率↑、基地愿续费/愿背书

## 八、技术架构

```
┌──────────────┐
│  学员/考官/管理员  │  Web端（React）· 语音输入
└──────┬───────┘
       │
┌──────▼───────┐
│  语音服务       │  ASR（中文语音识别）+ TTS（语音合成）
├──────────────┤
│  医疗大模型底座   │  医疗LLM（HuatuoGPT-II等开源底座或国产闭源API）
├──────────────┤
│  病例/评分引擎   │  病例脚本 + OSCE评分表 + 评分模型
├──────────────┤
│  数据平台       │  训练数据、成绩、通过率预测（结构化，可发RWE）
└──────────────┘
```

**关键选型：**
- 医疗LLM：先接国产闭源API（DeepSeek/豆包等）快速上线，验证后再考虑微调开源底座
- 数据合规：训练数据脱敏存储，符合《数据安全法》《个人信息保护法》
