# 住培AI OSCE训练系统 · 产品设计文档

> **版本：** v1.0
> **日期：** 2026-10-19
> **定位：** 面向住培基地的AI OSCE模拟训练与自动评分系统
> **首个试点：** 邵逸夫医院急诊科

---

## 一、产品概述

### 1.1 产品是什么
一个让住培学员通过与AI虚拟病人对话，模拟急诊问诊全过程，并获得AI自动评分与反馈的训练系统。

### 1.2 解决什么问题
- 学员缺少OSCE模拟训练机会（标准化病人约不到）
- 带教老师评分耗时、标准不统一
- 学员不知道自己哪里薄弱、真实水平如何

### 1.3 核心价值
- **学员：** 随时随地练、即时反馈、知道自己哪里错
- **带教老师：** AI先评一遍，老师只复核，减负
- **基地：** 训练数据可追溯、可分析、可对比

---

## 二、用户角色与权限

| 角色 | 使用场景 | 核心功能 |
|------|---------|---------|
| **住培学员** | 日常训练、模拟考核 | 选病例、问诊、看评分报告 |
| **带教老师** | 布置训练、复核评分、看班级数据 | 病例管理、评分复核、班级看板 |
| **基地管理员** | 学员管理、排班、看整体数据 | 学员管理、训练统计、数据导出 |

## 三、核心功能模块

### 3.1 模块一：AI虚拟病人问诊

**功能描述：** 学员选择病例后，通过文字与AI虚拟病人对话，模拟急诊问诊全过程。

#### 3.1.1 病例选择页
- 按专科分类（MVP先做急诊）
- 每个病例显示：病例名称、难度、预计时长、历史完成次数
- 学员可自由选择，也可做老师布置的任务

#### 3.1.2 问诊界面
```
┌─────────────────────────────────┐
│ 病例：急性胸痛（急性心梗）        │
│ 倒计时：05:32                   │
├─────────────────────────────────┤
│ 病人：男，58岁，胸痛2小时        │
│                                 │
│ 学员：你哪里不舒服？              │
│ 病人：胸口闷痛，像压了块石头      │
│ 学员：痛了多久？                 │
│ 病人：两个多小时了，一直没缓解    │
│ ...                             │
├─────────────────────────────────┤
│ [输入框]  [发送]                │
└─────────────────────────────────┘
```

#### 3.1.3 病情动态变化
- 问诊过程中，病人状态会根据病情逻辑变化
- 例：急性心梗病例，学员问了3分钟还没问到关键信息，病人可能说"我有点喘不上气"（提示病情加重）
- 目的：模拟急诊真实场景，训练学员快速抓住重点

#### 3.1.4 多角色对话（MVP后期）
- 病人 + 家属（情绪激动）+ 护士（报危急值）
- 学员需要跟多方沟通，不只是跟病人对话

---

### 3.2 模块二：AI考官自动评分

**功能描述：** 问诊结束后，AI按OSCE评分表自动评分，即时给出反馈报告。

#### 3.2.1 评分维度（7个）

| 维度 | 权重 | 评分要点 |
|------|------|---------|
| **1. 分诊判断** | 15% | 是否正确判断病情严重程度、是否识别濒危信号 |
| **2. 病史采集** | 15% | 关键症状是否问到（起病时间、性质、放射痛、诱因、伴随症状） |
| **3. 重点查体** | 15% | 是否做了针对主诉的重点查体（不是全身乱查） |
| **4. 初步诊断/鉴别** | 20% | 诊断思路是否正确、是否覆盖致命性鉴别诊断 |
| **5. 处置决策** | 20% | 检查/用药/会诊决策是否正确、是否及时 |
| **6. 医患沟通** | 10% | 沟通是否清晰、是否安抚病人/家属 |
| **7. 安全意识** | 5% | 是否识别红旗症状、是否漏致命风险 |

#### 3.2.2 评分报告页
```
┌─────────────────────────────────┐
│ 病例：急性胸痛（急性心梗）        │
│ 总分：72/100                    │
├─────────────────────────────────┤
│ 分诊判断：      85/100 ████████░│
│ 病史采集：      60/100 ██████░░░░│
│ 重点查体：      70/100 ███████░░░│
│ 初步诊断/鉴别： 75/100 ████████░░│
│ 处置决策：      65/100 ███████░░░│
│ 医患沟通：      80/100 ████████░░│
│ 安全意识：      70/100 ███████░░░│
├─────────────────────────────────┤
│ 你的薄弱点：病史采集、处置决策     │
│                                 │
│ 改进建议：                       │
│ · 胸痛病人要问放射痛（左肩/下颌） │
│ · 要问有没有出汗、恶心、呼吸困难  │
│ · 急性胸痛要先做心电图            │
└─────────────────────────────────┘
```

#### 3.2.3 评分方式
- **规则引擎：** 硬指标（关键病史点是否问到、分诊分级是否正确）
- **模型评分：** 软指标（诊断思路、沟通质量）
- **人机复核：** AI初评 + 带教老师抽检复核

---

### 3.3 模块三：教学管理后台

#### 3.3.1 学员管理
- 学员列表（姓名、科室、年级）
- 训练记录（完成了哪些病例、得分、用时）
- 个人能力雷达图（7个维度的历史趋势）

#### 3.3.2 病例管理
- 病例列表（名称、专科、难度、使用次数）
- 病例编辑（主诉、现病史、查体、鉴别诊断、评分点）
- 带教老师可审核/修改病例

#### 3.3.3 班级看板
- 班级平均分
- 各维度平均分
- 薄弱点排名（哪个维度全班都差）
- 学员进步趋势

## 四、5个核心病例设计（MVP）

### 病例1：急性心肌梗死（ACS）

| 项目 | 内容 |
|------|------|
| **主诉** | 胸骨后压榨性疼痛2小时 |
| **现病史** | 男，58岁，2小时前无明显诱因出现胸骨后压榨性疼痛，向左肩放射，伴大汗、恶心。休息不缓解。 |
| **既往史** | 高血压10年，吸烟30年 |
| **关键病史点** | 起病时间、疼痛性质、放射痛、伴随症状（大汗/恶心/呼吸困难）、诱因 |
| **重点查体** | 生命体征、心肺听诊 |
| **鉴别诊断** | 主动脉夹层、肺栓塞、心包炎、消化道穿孔 |
| **处置要点** | 立即心电图、心电监护、吸氧、建立静脉通路、心内科会诊 |
| **红旗症状** | 持续胸痛>20分钟、大汗、血压下降 |

### 病例2：主动脉夹层

| 项目 | 内容 |
|------|------|
| **主诉** | 突发撕裂样胸痛1小时 |
| **现病史** | 男，65岁，1小时前突发胸背部撕裂样疼痛，剧烈难忍，向腹部放射。既往高血压20年，控制不佳。 |
| **关键病史点** | 疼痛性质（撕裂样）、放射方向、双侧血压是否对称 |
| **鉴别诊断** | 急性心梗、肺栓塞、急腹症 |
| **处置要点** | 控制血压、心率，CTA确诊，血管外科会诊 |
| **易错点** | 容易误诊为心梗，忽略双侧血压差异 |

### 病例3：急性阑尾炎

| 项目 | 内容 |
|------|------|
| **主诉** | 转移性右下腹痛6小时 |
| **现病史** | 男，25岁，6小时前脐周痛，后转移至右下腹，伴恶心、低热。 |
| **关键病史点** | 疼痛转移过程、伴随症状（恶心/呕吐/发热） |
| **重点查体** | 麦氏点压痛、反跳痛、肌紧张 |
| **鉴别诊断** | 输尿管结石、宫外孕、胆囊炎、肠炎 |
| **处置要点** | 血常规、腹部超声、普外科会诊 |

### 病例4：急性脑卒中

| 项目 | 内容 |
|------|------|
| **主诉** | 突发右侧肢体无力伴言语不清2小时 |
| **现病史** | 女，70岁，2小时前突发右侧肢体无力，说话含糊不清。有房颤病史。 |
| **关键病史点** | 起病时间（时间窗！）、FAST（面部/上肢/言语）、既往病史 |
| **处置要点** | 立即头颅CT、神经内科会诊、溶栓时间窗判断 |
| **红旗症状** | 发病时间<4.5小时（溶栓窗）、意识障碍加重 |

### 病例5：多发伤

| 项目 | 内容 |
|------|------|
| **主诉** | 车祸伤后全身多处疼痛30分钟 |
| **现病史** | 男，35岁，车祸后被送来，意识清楚但烦躁，诉胸痛、腹痛、左大腿畸形。 |
| **关键病史点** | 受伤机制、意识变化、出血情况 |
| **重点查体** | ABCDE评估（气道/呼吸/循环/神经/暴露） |
| **处置要点** | 气道管理、止血、建立大口径静脉通路、骨科/普外科会诊 |
| **易错点** | 只看表面伤，忽略内出血/颅脑损伤 |

## 五、用户旅程

### 5.1 学员训练流程
```
登录系统
  ↓
选择病例（或做老师布置的任务）
  ↓
开始问诊（倒计时开始）
  ↓
与AI病人对话（文字输入）
  ↓
问诊结束（或时间到）
  ↓
AI自动评分（几秒出结果）
  ↓
查看评分报告（7维度得分+改进建议）
  ↓
下次训练（针对薄弱点选病例）
```

### 5.2 带教老师工作流程
```
登录系统
  ↓
查看班级看板（整体数据）
  ↓
发现某个学员某维度得分低
  ↓
查看该学员的问诊记录（AI评分明细）
  ↓
复核/调整评分
  ↓
给学员写评语/建议
```

## 六、界面设计要点

### 6.1 学员端
- **简洁为主：** 问诊界面不要太复杂，聚焦对话
- **倒计时醒目：** 急诊场景要有紧迫感
- **报告清晰：** 7维度得分一目了然，薄弱点突出
- **移动端适配：** 学员可能在手机上练

### 6.2 带教老师端
- **数据看板：** 班级整体情况一眼看到
- **快速复核：** AI评分明细清楚，老师只需调整有异议的部分
- **批量操作：** 可批量看学员、批量发任务

## 七、技术架构（产品视角）

### 7.1 系统组成
```
前端（Web/小程序）
  ↓
后端API服务
  ↓
医疗LLM（问诊对话生成）
  ↓
评分引擎（规则+模型）
  ↓
数据库（病例/对话/评分/用户）
```

### 7.2 关键技术选型
| 模块 | 选型 | 说明 |
|------|------|------|
| 医疗LLM | DeepSeek/豆包API | MVP快速上线 |
| 前端 | React Web + 微信小程序 | 学员多端可用 |
| 后端 | Node.js/Python | 快速开发 |
| 数据库 | PostgreSQL + Redis | 结构化数据+缓存 |
