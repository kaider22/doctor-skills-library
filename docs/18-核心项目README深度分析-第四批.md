## 一、临床试验与真实世界研究（RWE）方向（7个）⭐最匹配企业侧变现

> 这一组全部是给药企临床运营、医学部、RWE 团队用的工具链，是你"不向医生患者收费、全部企业侧变现"铁律里最对口的一块。

### 1. LibreClinica（reliatec-gmbh）
- **Star：** 80 | **许可证：** LGPL-3.0 | **语言：** Java | **最近更新：** 2026-10-11
- **真实是什么：** OpenClinica 的社区继任者，开源 EDC（电子数据捕获）+ CDM（临床数据管理）系统，真实生产级软件，不是论文 demo。
- **核心功能：** 建研究、eCRF 设计、访视排程、数据录入、数据质疑管理、审计追踪、电子签名、权限控制。
- **你的机会：** 给药企/CRO 做临床试验数据管理的二次开发底座。相比 OpenClinica 商业版，LGPL-3.0 允许你在其上做商用衍生（需开源修改部分）。可作为你"高血压随访产品"在医院端的合规数据录入范式参考。

### 2. teal（insightsengineering，Roche 旗下）
- **Star：** 263 | **许可证：** Other（开源但非 OSI 标准，需看条款）| **语言：** R | **最近更新：** 2026-10-14
- **真实是什么：** Roche/Genentech 开源的临床试验数据探索性 Shiny Web 应用框架，CRAN 在架，项目状态 Active，非常活跃。
- **核心功能：** 让临床数据科学家快速搭出可交互的临床试验数据探索 Web 应用（模块式接入数据与分析模块）。
- **你的机会：** 这是给药企做"数据自助探索"产品的现成框架。你做 RWE 报告工具时，可以参考它如何把庞杂的临床试验数据包装成业务人员能点的界面——B端报告产品的交互范式直接抄。

### 3. tern（pharmaverse）
- **Star：** 108 | **许可证：** Other | **语言：** R | **最近更新：** 2026-10-11
- **真实是什么：** pharmaverse（药企开源联盟）出品的临床试验 TLG（Table/Listing/Graphs）标准输出库。
- **核心功能：** 生成临床试验报告里那一堆标准的表格、列表、图形（入组表、基线特征表、暴露汇总等监管格式）。
- **你的机会：** 药企交付监管报告时 TLG 是重人力环节。你可以围绕它做"AI 自动生成 TLG"的产品——把分析师从机械制表里解放出来，卖给药企统计编程团队。这是典型的企业侧、按项目收费。

### 4. safetyGraphics（SafetyGraphics）
- **Star：** 102 | **许可证：** Other | **语言：** R | **最近更新：** 2023-10（更新放缓）
- **真实是什么：** 临床试验安全性图形 R 包，把不良事件、实验室异常、死亡等安全数据做成标准可视化。
- **核心功能：** 标准化安全监测图表（HBLD 图、不良事件时间线等）。
- **你的机会：** 项目已停更两年，不建议直接用，但它定义的"临床试验安全图形规范"值得参考。给药企药物警戒（PV）团队做安全信号可视化时，可对标这套标准。

### 5. clinical-trial-outcome-prediction（futianfan）
- **Star：** 173 | **许可证：** 未标注 | **语言：** Python | **最近更新：** 2025-06 | **发表：** Cell Patterns 2022
- **真实是什么：** 论文项目——临床试验获批概率预测，用 HINT（Hierarchical Interaction Network）深度学习方法。
- **核心功能：** 给定一个试验的属性（疾病、阶段、靶点、公司等），预测它最终能否获批。
- **你的机会：** 这是论文 demo，不是产品。但"预测试验成败/资产价值"这个需求，正是药企 BD、投资团队、CRO 想要的——你可以把它包装成"管线估值/立项决策"咨询工具，卖给药企 BD 和早期投资人。注意需自己重建数据集与验证。

### 6. CTKG（ninglab）
- **Star：** 69 | **许可证：** 未标注 | **语言：** Jupyter Notebook | **最近更新：** 2023-03
- **真实是什么：** 临床试验知识图谱（Clinical Trials Knowledge Graph），把 ClinicalTrials.gov 的试验、药物、疾病、靶点、人群连成图谱。
- **核心功能：** 机器可读的临床试验关系网络，支持多跳查询。
- **你的机会：** 给药企做"竞品试验监测""适应症空白发现"工具的数据底座。你的企业侧 RWE 产品如果要回答"这个靶点还有哪些试验在做、招募到哪一步"，这就是现成图谱结构参考。项目停更，需自己爬取更新。

### 7. SAS-Clinical-Trials-Toolkit（wyp1125）
- **Star：** 121 | **许可证：** GPL-3.0 | **语言：** SAS | **最近更新：** 2017（很老）
- **真实是什么：** SAS 脚本集，生成 SDTM 域、ADaM 数据集、Define.xml——临床试验数据标准化的监管交付物。
- **核心功能：** 把原始数据转成 FDA/NMPA 要求的 SDTM/ADaM 标准结构。
- **你的机会：** 虽老且 GPL-3.0（传染性强，商用要谨慎），但它把 SDTM/ADaM 的映射逻辑讲清楚了。中国药企出海做国际多中心试验时 SDTM 交付是刚需痛点，你若做"AI 辅助 SDTM 映射"服务，这是技术入门资料。

## 二、Meta分析与医学统计方向（4个）⭐给药企MSL/医学部

### 8. metafor（wviechtb）
- **Star：** 314 | **许可证：** 未标注（学术免费）| **语言：** R | **最近更新：** 2026-09
- **真实是什么：** R 里最常用、最权威的 meta 分析包，学术圈事实标准。
- **核心功能：** 固定/随机效应模型、亚组分析、meta 回归、发表偏倚检验、森林图/漏斗图。
- **你的机会：** 不是产品，是引擎。你做"给药企 MSL 的文献汇总/meta 分析自动化"产品时，统计计算底层就该接这个包（和你已分析的 meta-pipe 工作流组合）。它本身免费，但你上面包一层 AI 自动化与合规审计就是收费产品。

### 9. NiMARE（neurostuff）
- **Star：** 215 | **许可证：** MIT | **语言：** Python | **最近更新：** 2026-10
- **真实是什么：** Python 写的神经影像坐标/图像 meta 分析工具，MIT 可商用。
- **核心功能：** 对 fMRI/PET 脑成像研究做坐标-based meta 分析（CBMA）。
- **你的机会：** 垂直在神经科学领域，偏科研。如果你服务的药企有中枢神经（CNS）管线，可以参考它；否则优先级放低。MIT 许可友好。

### 10. Doing-Meta-Analysis-in-R（MathiasHarrer）
- **Star：** 511 | **许可证：** 未标注（配套在线书）| **语言：** R | **最近更新：** 2026-07
- **真实是什么：** 知名在线教程《Doing Meta-Analysis with R: A Hands-On Guide》的全部配套代码，read-only 仓库。
- **核心功能：** 手把手从数据导入到出图出结论的完整 meta 分析流程代码。
- **你的机会：** 不是产品，是教学素材。你给药企 MSL 做"meta 分析培训"或构建 AI 工具的提示词模板时，这套流程代码是权威蓝本。

### 11. MedStatForge（EXIST-D）⭐本批重点关注
- **Star：** 6 | **许可证：** 未标注 | **语言：** Python | **最近更新：** 2026-08
- **真实是什么：** **中文**、本地优先的"Agent + RAG 医学统计工作台"，Docker Compose 一键编排，专为单个研究者设计。
- **核心功能：**
  - 项目级私有知识库 RAG：PDF/DOCX/XLSX 上传，bge-m3 稠密 + Milvus BM25 稀疏混合检索，L1/L2/L3 父子分块，引用可溯源到页码
  - LangGraph 会话型研究 Agent，但**关键设计：模型不能直接调用统计执行或读取患者级原始数据**，`confirm/execute/R运行` 必须人工 HITL 确认
  - 从论文提取结构化 MethodProfile，做复现映射
  - 证据不足/冲突时明确暴露不确定性，不把推测包装成事实
- **你的机会：** 这个 6 星小项目反而最值得你抄作业。它的"Agent 只能出方案、统计执行必须人工确认"的 HITL 设计，完美契合你"不向医生收费、但要合规"的底线——给药企医学部做可审计的统计分析助手时，这就是合规架构模板。中文原生、本地部署，企业数据不出门，药企最爱。

## 三、文献/数据 MCP 与 FHIR 编码方向（2个）⭐企业数据基础设施

### 12. healthcare-mcp-public（Cicatriiz）⭐重点
- **Star：** 131 | **许可证：** MIT | **语言：** JavaScript/Node | **最近更新：** 2025-08
- **真实是什么：** 一个打包好的医疗 MCP Server，把多个权威医疗数据源封装成 AI 助手可调用的工具，MIT 可商用。
- **核心功能（实测 README）：**
  - FDA 药品信息检索、PubMed 文献检索、Health.gov 健康主题
  - ClinicalTrials.gov 临床试验检索、medRxiv 预印本
  - **ICD-10 编码与医学术语查询**
  - DICOM 元数据提取、BMI 医学计算器、NCBI Bookshelf
  - 缓存与连接池、匿名用量统计、stdio + HTTP/SSE 双接口、Swagger 文档
  - 提供一键安装的 DXT 扩展，`npm install healthcare-mcp` 即用
- **你的机会：** 这是你"仝学/B端文献证据产品"的现成瑞士军刀。你已分析过 OpenEvidence MCP（偏循证问答）和 omophub-mcp（偏术语），这个项目把 FDA+PubMed+试验+ICD-10+DICOM 一次性打包。给药企做"医学信息一站查询"工具时，直接基于它扩展，省掉你逐个对接 API 的工程量。MIT 许可友好，可商用。

### 13. lab-report-to-fhir-skill（terravic）⭐重点
- **Star：** 0 | **许可证：** Apache-2.0 | **语言：** HTML/Python | **最近更新：** 2026-09
- **真实是什么：** 化验单 PDF → HL7 FHIR R4 JSON 的转换工具包 + Agent Skill，Apache-2.0 可商用。0 星但工程完成度高。
- **核心功能（实测 README）：**
  - 把非结构化/半结构化化验单 PDF 转成标准 FHIR R4 资源：Patient、Observation、DiagnosticReport、Specimen、Bundle
  - 用 LOINC / SNOMED CT 本体做编码映射
  - **特别支持肿瘤场景：MCED 多癌早筛 cfDNA 甲基化、液体活检 ctDNA、遗传性肿瘤 NGS panel、生物标志物免疫检测**
  - 带交互式 Web UI Dashboard 可视化、CLI、Python API、合成测试数据
  - 明确声明所有示例数据为合成数据，零真实 PHI
- **你的机会：** 这是你"高血压随访产品化验单自动结构化"的直接可复用组件，而且它比你想象的更进一步——已经把肿瘤精准检测报告（cfDNA/NGS）也覆盖了。给药企 RWE 团队做"多来源检测报告结构化入库"，这是核心管道。Apache-2.0 无传染风险，0 星意味着没人跟你抢，是你的先发窗口。

## 五、医疗 Agent 训练与基座方向（3个）

### 15. Healthcare_GYM（minstar）⭐重点
- **Star：** 10 | **许可证：** Apache-2.0 | **语言：** Python | **最近更新：** 2026-08 | **论文：** arXiv 2605.02943
- **真实是什么：** 面向医疗 Agent 的强化学习训练环境（Gymnasium 兼容），把"静态知识检索"升级成"多轮临床工具调用执行"。
- **核心功能（实测 README）：**
  - 10 个临床领域、3.6K+ 任务、135 个领域专用工具、82.8 万篇医学文献知识库
  - 5D 安全感知奖励函数；提出 TT-OPD 自蒸馏框架

- **你的机会：** 它的"11 个医疗 MCP 一键打包进一个 Docker"是金矿——你做企业部署时，最头疼的就是给客户逐个配 MCP 环境，这个镜像直接帮你把部署成本打下来。它的 5D 安全奖励函数思路，也可用于你训练/评估自己医疗 Agent 的安全性。

## 八、累计78个项目后，对创业方向的新增结论

前三批58个项目帮你搭好了"模型+知识图谱+术语+文献+合规架构"的技术底座，结论是"可以开始做 MVP 了"。这第四批20个**临床试验/RWE工具链**项目，补全了你商业模式里最关键的一块——**企业侧到底怎么收钱、收谁的钱**。三个新增判断：

1. **最肥的企业侧钱在"临床试验/RWE交付自动化"，不在 C 端。** 这一批里 LibreClinica（EDC）、teal（数据探索）、tern（TLG制表）、metafor（meta分析）、CTKG（试验图谱）、clinical-trial-outcome-prediction（试验成败预测）——整条链都是给药企临床运营、统计编程、医学部、BD、RWE 团队用的。这些环节人力极贵、重复性极强、药企付费毫不含糊。你的"不向医生患者收费"铁律，在这里得到最强印证：**真正愿意为 AI 付年费的是药企的临床/医学/RWE 部门，不是一线医生。**

2. **"数据结构化 + FHIR/编码"是贯穿所有产品的隐形收费点。** lab-report-to-fhir-skill（化验单/肿瘤报告→FHIR）、healthcare-mcp-public（ICD-10/术语）、加上前三批的 omophub-mcp、medical-codes-mcp——你会发现企业侧产品的核心价值根本不是"聊天"，而是"把乱七八糟的临床数据变成机器可读、可统计、可入库的标准结构"。这是药企 RWE 和商保最愿意买单的基础设施。建议你把"临床报告自动结构化+编码"做成一个独立的中间件产品，复用到随访、RWE、商保核赔多个场景。

3. **合规架构的标准答案已经收敛：Agent 只出方案，执行必须人工确认（HITL）。** MedStatForge 和 Healthcare_GYM 不约而同地采用了"模型不能直接跑统计/读原始患者数据，关键动作必须人工 confirm"的设计。这给你的产品定了形：**面向药企/B端的医疗 AI，要卖的不是"全自动无人值守"，而是"可审计、可追溯、人在回路"——这恰恰是企业采购最看重、也最容易过内部合规评审的卖点。** 把这个写进你的产品白皮书中，作为差异化定位。
