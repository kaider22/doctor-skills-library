## 1. medkit-app — AI患者模拟器

### 基本信息
- **Star：** 333 | **语言：** TypeScript | **许可证：** 未标注
- **主页：** https://medkit-app.vercel.app/

### 它到底是什么
这是一个**黑客马拉松项目**，3天做出来的，作者是一个转行做软件的医生。
- 模拟急诊室+门诊两种场景
- 你扮演医生，和AI患者实时语音对话
- 开检查、读影像、诊断、开处方
- Claude Opus 4.7扮演"主治医生"给你评分，引用NICE/ESC/AHA等指南

### 技术栈
| 层 | 技术 |
|---|---|
| 前端 | React 18 + TypeScript + Vite + Three.js |
| 语音 | LiveKit Cloud (WebRTC) |
| 语音工作流 | Python livekit-agents → Deepgram STT → Claude Haiku → Cartesia TTS |
| 后端 | FastAPI |
| 评分系统 | Claude Opus 4.7 (Managed Agent) |

### 实际可用性评估
- **优点：** 技术架构清晰，语音交互完整，OSCE评分逻辑可参考
- **缺点：** 合成病例，不是真实临床数据；黑客马拉松项目，没经过临床验证
- **你能怎么用：** 参考它的技术架构（语音+评分+场景），做高血压随访沟通训练，给药企医学代表培训用
- **关键发现：** 它的评分系统引用了真实指南（NICE/ESC/AHA/GINA/GOLD），这个设计思路很好——不能编造指南来源

## 2. OpenEvidence MCP — 文献证据检索

### 基本信息
- **Star：** 78 | **语言：** TypeScript | **许可证：** Apache-2.0

### 它到底是什么
这是一个**非官方OpenEvidence接口**，解决了一个核心问题：
- OpenEvidence有bot检测，直接调API会被拦
- 这个项目通过**浏览器扩展**的方式，让AI工具通过你自己登录的浏览器tab来查询OpenEvidence
- 不需要API key，你的浏览器登录就是凭证

### 工作原理
```
Claude/Codex → MCP Server → relay daemon → 浏览器扩展 → 你登录的OpenEvidence tab
```

### 实际可用性评估
- **优点：** 直接可用，不用API key，BibTeX引用+Crossref验证
- **缺点：** 非官方，依赖你自己的OpenEvidence账号；有bot检测被封的风险
- **你能怎么用：** 直接用在你的仝学项目里，让医生可以用Claude Code查询医学文献证据
- **关键发现：** 这个项目的核心创新是"浏览器扩展作为认证桥梁"——绕过bot检测但不破坏认证，这个思路可以复用到其他有反爬的医学数据库

## 3. meta-pipe — meta分析自动化

### 基本信息
- **Star：** 144 | **语言：** Python | **许可证：** 学术非商业

### 它到底是什么
Claude Code驱动的**端到端meta分析自动化工具**，9个阶段pipeline：
1. 协议生成（PICO、入排标准）
2. 文献检索
3. 文献筛选
4. 数据提取
5. 质量评估
6. 统计分析
7. 结果可视化
8. 偏差评估
9. 生成论文初稿

### 实际可用性评估
- **优点：** 完整的工作流，从研究问题到论文初稿；Claude Code驱动，自然语言交互
- **缺点：** 学术非商业许可证，不能直接商用；需要Claude Code
- **你能怎么用：** 给药企MSL做文献汇总工具——把它的工作流思路搬过来，做成产品化的工具，客单价10-30万/项目
- **关键发现：** 它的9阶段pipeline就是给药企做meta分析的标准流程，你可以直接把这个流程做成SaaS

## 4. human-atlas — 3D解剖浏览器

### 基本信息
- **Star：** 4250 | **语言：** TypeScript | **许可证：** CC BY 4.0

### 它到底是什么
开源3D解剖浏览器：
- 2234个可选择的BodyParts3D网格
- 15个解剖系统
- 3432个命名概念
- React + Three.js + shadcn/ui构建
- 支持旋转、缩放、搜索、爆炸视图

### 实际可用性评估
- **优点：** 数据完整（BodyParts3D 4.0），技术栈现代，CC BY 4.0可商用
- **缺点：** 男性参考模型，不代表所有人体结构；是教育探索工具，不是诊断/手术工具
- **你能怎么用：** 直接拿来做解剖教学平台——加GPT问答、加解剖考试、加科室专属内容，卖给医学院
- **关键发现：** 它的33MB压缩几何体、228万三角形——这个性能优化做得很好，可以直接部署到Web端

## 5. Clinical-Trial-Parser (Facebook) — 临床试验方案解析

### 基本信息
- **Star：** 186 | **语言：** Go | **许可证：** 未标注（Facebook Research项目）

### 它到底是什么
Facebook AI开源的**临床试验入排标准解析工具**：
- 用CFG（上下文无关文法）+ 信息提取
- 把临床试验的入排标准文本转成机器可读的布尔逻辑
- 这样就可以自动匹配患者和试验

### 解决的问题
- 临床试验招募不到足够患者
- 找不到相关试验，符合条件的患者很少报名
- 入排标准是人写的文本，机器读不懂

### 实际可用性评估
- **优点：** Facebook AI出品，技术成熟；解决的是真实痛点（试验招募难）
- **缺点：** Go语言写的，需要一定技术能力；可能只支持英文
- **你能怎么用：** 给药企做临床试验方案自动化——把入排标准结构化，自动匹配患者；客单价20-50万/项目
- **关键发现：** 它的核心是把自然语言的入排标准转成布尔逻辑（I1 AND I2 AND NOT E1...），这个思路非常聪明

## 六、深度分析后的结论

### 真正能直接用的（不用改代码）
1. **human-atlas** — 直接拿来做解剖教学平台，加GPT问答就是产品
2. **OpenEvidence MCP** — 直接装在你电脑上，仝学项目就能用

3. **meta-pipe** — 工作流思路很好，把它做成产品化的SaaS

- **meta-pipe** — 学术非商业许可证，不能直接商用，要自己重做
- **OpenEvidence MCP** — 非官方接口，有被封风险
- **human-atlas** — CC BY 4.0，商用要署名
