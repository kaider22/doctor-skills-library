## 一、产品概述

### 1.1 产品定位

面向中国住院医师规范化培训基地的AI虚拟病人OSCE训练与自动评分系统。通过LLM驱动的AI虚拟病人，让住培学员随时随地进行临床问诊模拟训练，并获得AI自动评分与结构化反馈，减轻带教老师负担，提升培训质量。

### 1.2 解决的核心问题

| 问题 | 现状 | 我们的方案 |
|------|------|-----------|
| OSCE训练机会少 | 标准化病人（SP）昂贵、约不到 | AI虚拟病人，无限次练习 |
| 评分标准不统一 | 带教老师主观差异大 | AI按统一评分表自动评分 |
| 学员不知道自己哪里弱 | 训练后缺乏反馈 | 7维度评分报告+改进建议 |
| 老师评分耗时 | 一个学员问诊10分钟，评分也要10分钟 | AI初评，老师只复核 |
| 训练数据难积累 | 纸质记录，无法分析 | 全流程数据数字化 |

### 1.3 目标用户

| 角色 | 画像 | 核心诉求 |
|------|------|---------|
| **住培学员** | 22-30岁，本科/硕士，刚进基地1-3年 | 多练、知道自己哪里错、模拟考核 |
| **带教老师** | 主治及以上，负责住培教学 | 减负、统一评分标准、班级数据 |
| **基地教学主任** | 副高及以上，负责整个基地培训 | 培训质量可量化、可追溯、迎检 |

### 1.4 商业原则（铁律）

- 不向医生和患者收取任何费用
- 基地和学员免费使用
- 商业价值来自企业侧（药企学术教育赞助、器械企业培训等）

## 三、功能模块详细需求

### 3.1 模块一：学员端 · 问诊训练

#### 3.1.1 首页/病例选择

**功能描述：** 学员登录后看到的第一个页面，选择要训练的病例。

**需求点：**
- [ ] 显示学员姓名、科室、年级
- [ ] 病例列表按专科分类（MVP只有急诊）
- [ ] 每个病例卡片显示：病例名称、难度（⭐1-5）、预计时长、已完成次数
- [ ] 老师布置的任务标"必做"标签
- [ ] 搜索功能：按病例名搜索
- [ ] 筛选：按难度、按是否完成、按专科

**交互流程：**
1. 学员打开小程序 → 看到病例列表
2. 点击某个病例 → 进入病例详情页
3. 点击"开始训练" → 进入问诊界面

**验收标准：**
- 病例列表加载时间 < 1秒
- 病例信息完整显示

#### 3.1.2 问诊界面（核心）

**功能描述：** 学员与AI虚拟病人对话的主界面。

**需求点：**
- [ ] 顶部显示：病例名称、倒计时（默认15分钟）、退出按钮
- [ ] 中间：对话气泡区域（学员消息右侧绿色，病人消息左侧白色）
- [ ] 底部：输入框 + 发送按钮 + 语音输入按钮（V2）
- [ ] 病人头像（不同病例不同头像）
- [ ] 病情变化提示：当病人状态变化时，对话中体现（如"病人突然捂住胸口，表情痛苦"）
- [ ] 紧急情况：病人病情恶化时，顶部变红闪烁提示

**交互流程：**
1. 学员输入问题 → 发送 → AI病人回答
2. 学员可以追问任何问题
3. 时间到 → 自动结束问诊 → 进入评分环节
4. 学员也可以手动点击"问诊结束" → 进入评分

**病情动态变化逻辑：**
- 每个病例预设时间轴状态机
- 例：急性心梗病例
  - 0-3分钟：病人平稳，描述胸痛
  - 3-5分钟：学员还没问到关键信息 → 病人说"我有点喘不上气，越来越难受"
  - 5分钟以上：病人说"我眼前发黑了..."（提示如果再不处理就危险了）
- 目的：模拟急诊真实压力，训练学员快速抓住重点

**验收标准：**
- 对话响应时间 < 3秒
- 病人回答符合病例设定的病情和人格
- 病情动态变化按预设时间轴触发

#### 3.1.3 语音问诊（V2）

**功能描述：** 学员可以用语音跟AI病人对话，不用打字。

**需求点：**
- [ ] 按住说话按钮 → 录音 → 松开后转文字 → 发送给AI病人
- [ ] AI病人的回答自动转成语音播放
- [ ] 语音识别准确率 > 90%（医疗术语场景）
- [ ] 病人音色可切换（不同病例不同音色）

**技术实现：**
- ASR：FunASR（中文医疗优化）
- TTS：ChatTTS（多音色）

### 3.2 模块二：评分与反馈

#### 3.2.1 AI自动评分

**功能描述：** 问诊结束后，AI自动按7个维度评分。

**评分维度（7个）：**

| 维度 | 权重 | 评分要点 | 评分方式 |
|------|------|---------|---------|
| 1. 分诊判断 | 15% | 是否正确判断病情严重程度、是否识别濒危信号 | 规则引擎 |
| 2. 病史采集 | 15% | 关键症状是否问到（起病时间、性质、放射痛、诱因、伴随症状） | 规则引擎+LLM |
| 3. 重点查体 | 15% | 是否做了针对主诉的重点查体 | 规则引擎 |
| 4. 初步诊断/鉴别 | 20% | 诊断思路是否正确、是否覆盖致命性鉴别诊断 | LLM评分 |
| 5. 处置决策 | 20% | 检查/用药/会诊决策是否正确、是否及时 | 规则引擎+LLM |
| 6. 医患沟通 | 10% | 沟通是否清晰、是否安抚病人/家属 | LLM评分 |
| 7. 安全意识 | 5% | 是否识别红旗症状、是否漏致命风险 | 规则引擎 |

**评分流程：**
1. 问诊结束 → 系统自动收集整个对话记录
2. 规则引擎先评硬指标（关键病史点是否问到、分诊分级是否正确）
3. LLM评软指标（诊断思路、沟通质量）
4. 汇总7个维度得分 → 计算总分（百分制）
5. 生成改进建议

**验收标准：**
- 评分计算时间 < 5秒
- 评分结果与带教老师人工评分一致性 > 80%（试点期校准）

#### 3.2.2 评分报告页

**功能描述：** 学员看到的评分结果页面。

**需求点：**
- [ ] 顶部：总分（大字号，百分制）
- [ ] 7维度得分雷达图（可视化）
- [ ] 各维度分项得分 + 简短点评
- [ ] 薄弱点提示：哪几个维度得分最低（标红）
- [ ] 改进建议：具体到这个病例，哪里问错了、该问什么
- [ ] 对话回顾：可以回看整个问诊过程
- [ ] "再练一次"按钮

**报告示例（急性心梗病例）：**
```
总分：72分
├─ 分诊判断：85分 ✅ 正确识别高危胸痛
├─ 病史采集：60分 ⚠️ 没问到放射痛和大汗
├─ 重点查体：70分 ⚠️ 没做心肺听诊
├─ 初步诊断：75分 ✅ 考虑心梗，但没提鉴别诊断
├─ 处置决策：65分 ⚠️ 没提心电图和心电监护
├─ 医患沟通：80分 ✅ 沟通清晰
└─ 安全意识：70分 ⚠️ 没识别"持续胸痛>20分钟"红旗

改进建议：
1. 下次注意问疼痛是否放射到左肩/左臂
2. 胸痛病人要常规做心电图和心电监护
3. 鉴别诊断要想到主动脉夹层
```

**验收标准：**
- 报告加载时间 < 2秒
- 雷达图清晰可读
- 改进建议具体、可操作

#### 3.2.3 实时过程反馈（V3 · 苏格拉底式）

**功能描述：** 问诊过程中，AI适时引导，不是结束后才评分。

**需求点：**
- [ ] 学员问了3分钟还没问到关键信息 → AI病人主动提示（"我这疼还串到肩膀了"）
- [ ] 学员问了无关问题 → AI病人不直接说"你问错了"，而是引导（"我主要是胸口疼，您要不要再问问这个？"）
- [ ] 学员做了错误判断 → AI不直接纠正，而是反问（"那您觉得我为什么会喘不上气呢？"）
- [ ] 引导频率：每个病例2-3次适时提示，不打断太多

**设计原则：** 苏格拉底式——不直接给答案，引导学员自己思考。

```

难度：⭐⭐⭐
预计时长：15分钟

病人画像：
- 男，58岁
- 性格：急躁型，有点不耐烦
- 语言水平：初中文化，医学知识少
- 病史回忆：记得清楚起病时间
- 认知状态：清楚

现病史：
- 2小时前无明显诱因出现胸骨后压榨性疼痛
- 向左肩放射
- 伴大汗、恶心
- 休息不缓解

既往史：
- 高血压10年，吃药不规律
- 吸烟30年，每天一包
- 否认糖尿病

关键病史点（评分点）：
[必问] 起病时间
[必问] 疼痛性质（压榨性/撕裂样）
[必问] 放射痛（左肩/左臂/下颌）
[必问] 伴随症状（大汗/恶心/呼吸困难）
[必问] 诱因（劳累/情绪激动/无）
[必问] 既往类似发作

重点查体（评分点）：
[必查] 生命体征（血压/心率/血氧）
[必查] 心肺听诊
[选查] 双肺呼吸音

鉴别诊断：
- 急性心肌梗死（主诊断）
- 主动脉夹层（必须提到）
- 肺栓塞（应该想到）
- 心包炎
- 消化道穿孔

处置决策（评分点）：
[必做] 立即心电图
[必做] 心电监护
[必做] 建立静脉通路
[必做] 心内科会诊
[选做] 吸氧
[选做] 镇痛

红旗症状：
- 持续胸痛>20分钟
- 大汗淋漓
- 血压下降
- 意识改变

病情动态时间轴：
- 0-3分钟：平稳，描述胸痛
- 3-5分钟：如果没问到关键信息 → "我有点喘不上气"

- 8分钟以上：如果还没叫会诊 → 病人声音微弱

易错点：
- 容易漏问放射痛
- 容易忽略主动脉夹层鉴别
- 容易忘记心电监护
```

### 3.4 模块四：老师端 · 教学管理

#### 3.4.1 学员管理

**功能描述：** 带教老师查看和管理学员列表。

**需求点：**

- [ ] 搜索学员
- [ ] 按科室/年级筛选

**学员个人详情页：**
- [ ] 基本信息
- [ ] 训练记录：完成了哪些病例、每次得分、用时
- [ ] 能力雷达图（7维度历史趋势）
- [ ] 薄弱点分析：哪个维度最差，怎么改进
- [ ] 可以给学员写评语

#### 3.4.2 评分复核

**功能描述：** AI初评后，带教老师复核评分。

**需求点：**
- [ ] 待复核列表：学员刚完成的训练
- [ ] 点击进入 → 看对话记录 + AI评分明细
- [ ] 老师可以调整各维度得分
- [ ] 可以写评语
- [ ] 确认后 → 学员看到最终评分

**设计原则：** AI初评，老师只复核有异议的部分，不重新评一遍。

#### 3.4.3 班级看板

**功能描述：** 班级整体数据概览。

**需求点：**
- [ ] 班级平均分
- [ ] 各维度平均分（7维度条形图）
- [ ] 薄弱点排名：全班哪个维度得分最低
- [ ] 学员进步趋势：最近一个月平均分变化
- [ ] 训练完成率：多少人完成了必做任务
- [ ] 可以按时间筛选（本周/本月/本季度）

## 四、非功能需求

### 4.1 性能要求

| 指标 | 要求 |
|------|------|
| 页面加载时间 | < 2秒 |
| AI对话响应时间 | < 3秒 |
| 评分计算时间 | < 5秒 |
| 并发支持 | MVP 100人同时在线 |
| 系统可用性 | 99.5% |

### 4.2 安全与合规

| 要求 | 说明 |
|------|------|
| 等保三级 | 按医疗信息系统安全等级保护要求 |
| 数据本地化 | 数据存在国内阿里云，不出境 |
| 数据脱敏 | 学员数据匿名化，不存真实姓名（用学号） |
| 个保法 | 符合个人信息保护法 |
| 医疗器械 | 定位"医学教育"，不做诊疗辅助，不碰二类/三类医疗器械注册 |

### 4.3 兼容性

|------|--------|

| 第5-6周 | 微信小程序学员端开发（病例选择+问诊+报告） |
| 第7-8周 | Web老师端开发（学员列表+评分复核+班级看板） |
| 第9-10周 | 联调测试；病例脚本校准；评分准确率校准 |
| 第11-12周 | 邵逸夫试点上线；收集反馈；迭代优化 |
