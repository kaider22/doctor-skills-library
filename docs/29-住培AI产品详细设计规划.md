# 住培AI产品 · 详细产品设计规划

> **版本：** v1.0
> **日期：** 2026-10-19
> **目标：** 邵逸夫医院急诊科首个试点 → 浙江住培基地规模化 → 出海复制
> **核心理念：** 入口免费攥数据、数据中台做壁垒、企业侧变现赚钱

---

## 一、产品定位与愿景

### 1.1 一句话定位
**给住培基地一套"AI虚拟标准化病人 + AI考官自动评分"的OSCE训练考核系统，用AI问诊当采集器，把临床思维行为变成结构化数据资产，最终卖给药企。**

### 1.2 愿景
- **短期（0-12月）：** 跑通邵逸夫急诊科试点，验证"学员愿用+评分准+科室认可"
- **中期（12-24月）：** 浙江49家住培基地渗透10%，落地第一笔药企学术教育赞助
- **长期（24-36月）：** 引擎复制出海，成为"医生能力数据资产平台"

### 1.3 核心铁律
- ❌ 不向医生个人收费
- ❌ 不向患者收费
- ❌ 不向医院临床科室收费
- ✅ 商业价值全部来自企业侧（药企/器械/商保）与教学机构B端

## 二、目标用户与痛点

### 2.1 目标用户分层

| 层级 | 用户 | 角色 | 核心痛点 |
|------|------|------|---------|
| **付费方** | 药企医学部 | 最终买单者 | 需要年轻医生学术教育触达、临床决策偏差数据 |
| **决策方** | 住培基地教学主任/教育处 | 拍板试点 | 通过率硬指标、考官人力不足、评分标准不统一 |
| **使用方** | 住培学员 | 高频用户 | 训练机会少、反馈不及时、不知道真实水平 |
| **辅助方** | 带教老师/考官 | 复核评分 | 评分耗时、主观、复盘麻烦 |

### 2.2 急诊科特有痛点（首个试点）
- **时间紧：** 急诊带教老师没时间盯每个学员练
- **病情变化快：** 模拟病人不会"恶化"，跟真实急诊差距大
- **决策难：** 学员在压力下分诊、判断、处置容易出错
- **多角色沟通：** 病人+家属+护士，场景复杂

## 三、核心功能模块

### 3.1 模块1：AI急诊虚拟病人（AI-EVSP）

**功能描述：** 学员通过文字/语音与AI虚拟病人对话，模拟急诊问诊全过程。

| 子功能 | 详细描述 |
|--------|---------|
| 病情动态引擎 | 问诊过程中病人状态变化（胸痛→晕厥、呼吸困难→发绀） |
| 时间压力 | 每个病例有倒计时（5-8分钟），模拟急诊紧迫感 |
| 多角色对话 | 病人+家属（情绪激动）+护士（报危急值） |
| 红旗症状识别 | AI评分重点看学员是否识别"必须立刻处理"的信号 |
| 病例库 | 按专科分类，MVP先做急诊5个核心病例 |

### 3.2 模块2：AI考官自动评分

**功能描述：** 问诊结束后，AI按OSCE评分表自动评分，即时反馈。

| 评分维度 | 权重 | 评分要点 |
|---------|------|---------|
| 分诊判断 | 15% | 分诊分级是否正确、是否识别濒危/危重 |
| 病史采集 | 15% | 关键症状（起病时间、性质、放射痛、诱因）是否问到 |
| 重点查体 | 15% | 是否做了针对主诉的重点查体（不是全身乱查） |
| 初步诊断/鉴别 | 20% | 思路是否正确、是否覆盖致命性鉴别诊断 |
| 处置决策 | 20% | 检查/用药/会诊决策是否正确、是否及时 |
| 医患沟通 | 10% | 时间紧情况下的沟通、家属安抚、知情告知 |
| 安全意识 | 5% | 红旗症状识别、危急值处理、是否漏致命风险 |

**评分方式：** 规则引擎（硬指标）+ 模型评分（软指标），AI初评 + 带教老师抽检复核

### 3.3 模块3：教学管理后台

| 子功能 | 详细描述 |
|--------|---------|
| 学员管理 | 建班、排班、训练计划 |
| 成绩分析 | 通过率预测、薄弱环节诊断、个体/班级对标 |
| 数据看板 | 对标国家标准、基地间匿名对比 |
| 病例管理 | 带教老师可审核/编辑病例脚本 |

### 3.4 模块4：药企洞察端（企业侧，后期开放）

| 子功能 | 详细描述 |
|--------|---------|
| 病例训练洞察 | 某专科年轻医生在哪类病例上推理偏差最大 |
| MSL触达报告 | 年轻医生学术教育内容需求分析 |
| RWE数据产品 | 脱敏的临床思维数据（远期） |

## 四、用户旅程

### 4.1 学员端旅程
```
登录 → 选病例 → 开始问诊（倒计时）
→ 与AI病人对话（文字/语音）
→ 问诊结束 → AI评分 + 反馈
→ 查看个人报告（能力雷达图）
→ 下次训练（针对薄弱点）
```

### 4.2 科室教学主任旅程
```
收到试点邀请 → 参观Demo → 同意试点
→ 学员使用3个月 → 看数据看板
→ 训练前后对比 → 认可效果 → 扩科室
```

### 4.3 药企旅程（远期）
```
联系合作 → 看脱敏数据样本
→ 投放病例库赞助 → 获MSL触达报告
→ 续费/扩科
```

## 六、数据资产设计（核心壁垒）

### 6.1 四个数据库

| 数据库 | 内容 | 作用 |
|--------|------|------|
| 病例库 | OSCE考纲对齐的结构化病例脚本 | 决定产品专业度 |
| 对话日志库 | 学员与AI虚拟病人的每一句对话 | **核心石油** |
| 评分库 | AI考官对每站的多维评分明细 | 能力量化 |
| 医生能力画像库 | 个体/基地/专科维度的能力雷达图 | 药企最想要的产品 |

### 6.2 数据中台流程
```
原始对话日志
   ↓ 清洗/脱敏/标准化
结构化临床思维数据
   ↓ 按专科/地区/基地聚合
医生能力洞察产品（给药企）
```

## 七、商业模式

### 7.1 收入结构（按优先级）

| 模式 | 付费方 | 定价 | 优先级 |
|------|--------|------|--------|
| **药企学术教育赞助** | 药企医学部 | 50-200万/科/年 | ⭐⭐⭐ 首选 |
| 基地教学服务 | 住培基地（按教学服务立项） | 80-120元/人/年 | ⭐⭐ 备选 |
| 出海复制 | 海外医学院/住培机构 | 按当地定价 | ⭐ 远期 |

### 7.2 为什么药企付费是首选
- 完全不踩铁律（不向医生/患者/医院科室收费）
- 药企学术教育预算充足（MSL/医学教育是标配预算）
- 数据越用越多，粘性越强

## 八、MVP计划（3个月）

### 8.1 MVP范围

| 维度 | MVP范围 |
|------|--------|
| 科室 | 邵逸夫医院急诊科 |
| 病例 | 5个核心病例（急性心梗、主动脉夹层、阑尾炎、脑卒中、多发伤） |
| 交互 | 文字问诊为主，先不做语音 |
| 时间压力 | 简单倒计时（5-8分钟） |
| 评分 | 7维度规则评分+基础模型评分 |
| 端 | 学员端+考官端（管理端极简） |
| 学员 | 10-15人 |
| 药企端 | 暂不开放，先攒数据 |

### 8.2 MVP验证目标

| 指标 | 目标 |
|------|------|
| 学员活跃率 | 每周至少练2次，3个月不流失 |
| AI评分 vs 人工评分一致性 | >80% |
| 学员主观反馈 | "比以前练得多"、"反馈及时" |
| 科室主任意愿 | 愿意再扩到其他科室 |

## 十一、风险与对策

| 风险 | 对策 |
|------|------|
| 基地不愿付费/采编周期长 | 路径B：免费换数据+药企买单 |
| 大厂免费bundled进教学系统 | 做垂直专科深度，绑定OSCE考纲 |
| 医疗AI监管 | 轻器械重证据，定位"医学教育"非"诊疗" |
| 数据合规 | 虚拟病人系统天然规避患者数据红线 |
| AI评分不准 | AI初评+带教老师复核，逐步校准 |
