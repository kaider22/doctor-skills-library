## 一、产品概述

### 1.1 产品定位

面向中国住院医师规范化培训基地的**AI虚拟病人OSCE训练与医学教育平台**。一个完整的临床能力训练平台，包含：AI虚拟病人问诊 + 自动评分 + 学习分析 + 考试题库 + 自适应学习，对标Osmosis + PatientSim + Socratic AI的完整能力。

### 1.2 解决的核心问题

| 问题 | 现状 | 我们的方案 |
|------|------|-----------|
| OSCE训练机会少 | 标准化病人昂贵、约不到 | AI虚拟病人，无限次练习 |
| 评分标准不统一 | 带教老师主观差异大 | AI按统一评分表自动评分 |
| 学员不知道自己哪里弱 | 训练后缺乏反馈 | 7维度评分+学习分析+趋势追踪 |
| 老师评分耗时 | 问诊10分钟，评分也要10分钟 | AI初评，老师只复核 |
| 训练数据难积累 | 纸质记录，无法分析 | 全流程数据数字化 |
| 学习资源分散 | 视频、题库、病例分开找 | 一站式平台：问诊+题库+考试 |

### 1.3 目标用户

| 角色 | 画像 | 核心诉求 |
|------|------|---------|
| **住培学员** | 22-30岁，本科/硕士，刚进基地1-3年 | 多练、知道自己哪里错、备考结业考核 |
| **带教老师** | 主治及以上，负责住培教学 | 减负、统一评分标准、班级数据、布置任务 |
| **基地教学主任** | 副高及以上，负责整个基地培训 | 培训质量可量化、可追溯、迎检 |

### 1.4 商业原则（铁律）

- 不向医生和患者收取任何费用
- 基地和学员免费使用
- 商业价值来自企业侧（药企学术教育赞助、器械企业培训等）

## 三、功能模块详细需求

### 3.1 模块一：问诊训练

#### 3.1.1 病例选择页

- 显示学员姓名、科室、年级
- 病例列表按专科分类（急诊/内科/外科/妇科/儿科等）
- 每个病例卡片：病例名称、难度（⭐1-5）、预计时长、已完成次数、上次得分
- 老师布置的任务标"必做"标签
- 搜索：按病例名搜索
- 筛选：按难度、按是否完成、按专科
- 推荐：根据学员薄弱点智能推荐病例

#### 3.1.2 问诊界面（核心）

- 顶部：病例名称、倒计时（默认15分钟）、退出按钮
- 中间：对话气泡区域（学员消息右侧绿色，病人消息左侧白色）
- 底部：输入框 + 发送按钮 + 语音输入按钮
- 病人头像（不同病例不同头像）
- 病情变化提示：当病人状态变化时，对话中体现
- 紧急情况：病人病情恶化时，顶部变红闪烁提示

**病情动态变化（对齐Body Interact）：**
- 每个病例预设时间轴状态机
- 例：急性心梗病例
  - 0-3分钟：病人平稳，描述胸痛
  - 3-5分钟：学员还没问到关键信息 → 病人说"我有点喘不上气"
  - 5-8分钟：学员还没做心电图 → 病人说"我眼前发黑了..."
  - 8分钟以上：病人声音微弱，提示再不处理就危险了
- 模拟急诊真实压力，训练学员快速抓住重点

#### 3.1.3 人格模拟系统（对齐PatientSim 37维度）

| 维度 | 等级 | 表现 |
|------|------|------|
| **性格类型** | 5种 | 合作型/急躁型/焦虑型/沉默型/易怒型 |
| **语言水平** | 3种 | 清晰流利/口音重/表达不清 |
| **病史回忆能力** | 3种 | 记得清楚/记不太清/混乱（时间线说错） |
| **认知状态** | 4种 | 完全清楚/有点糊涂/谵妄（胡言乱语）/痴呆 |

设计原则：不同病例配不同人格组合，同一种病也可以有不同人格的病人，增加训练复杂度。

#### 3.1.4 语音问诊

- 按住说话 → 录音 → 松开后转文字 → 发送给AI病人
- AI病人的回答自动转成语音播放
- 语音识别准确率 > 90%（医疗术语场景）
- 病人音色可切换（不同病例不同音色）
- 情绪变化：病人痛苦时声音虚弱/急促

#### 3.1.5 多角色对话

- 家属角色：在旁边说话、情绪激动、插话
- 护士角色：进来报危急值（"医生，血压掉到80/50了"）
- 学员可以选择跟谁对话
- 训练学员在复杂场景下的沟通和决策能力

### 3.2 模块二：评分与反馈

#### 3.2.1 AI自动评分

| 维度 | 权重 | 评分要点 | 评分方式 |
|------|------|---------|---------|
| 1. 分诊判断 | 15% | 是否正确判断病情严重程度、识别濒危信号 | 规则引擎 |
| 2. 病史采集 | 15% | 关键症状是否问到（起病时间、性质、放射痛、诱因、伴随症状） | 规则+LLM |
| 3. 重点查体 | 15% | 是否做了针对主诉的重点查体 | 规则引擎 |
| 4. 初步诊断/鉴别 | 20% | 诊断思路是否正确、是否覆盖致命性鉴别诊断 | LLM评分 |
| 5. 处置决策 | 20% | 检查/用药/会诊决策是否正确、是否及时 | 规则+LLM |
| 6. 医患沟通 | 10% | 沟通是否清晰、是否安抚病人/家属 | LLM评分 |
| 7. 安全意识 | 5% | 是否识别红旗症状、是否漏致命风险 | 规则引擎 |

评分流程：
1. 问诊结束 → 收集整个对话记录
2. 规则引擎评硬指标
3. LLM评软指标
4. 汇总7个维度得分 → 总分（百分制）
5. 生成改进建议

#### 3.2.2 评分报告页

- 顶部：总分（大字号，百分制）
- 7维度得分雷达图（可视化）
- 各维度分项得分 + 简短点评
- 薄弱点提示：哪几个维度得分最低（标红）
- 改进建议：具体到这个病例，哪里问错了、该问什么
- 对话回顾：回看整个问诊过程
- "再练一次"按钮
- "推荐相关训练"：根据薄弱点推荐其他病例

#### 3.2.3 苏格拉底式实时反馈（对齐Socratic AI）

- 问诊过程中，AI适时引导，不是结束后才评分
- 学员问了3分钟还没问到关键信息 → AI病人主动提示
- 学员问了无关问题 → AI引导，不直接说"你错了"
- 学员做了错误判断 → AI反问引导思考
- 引导频率：每个病例2-3次适时提示
- 设计原则：不直接给答案，引导学员自己思考

### 3.3 模块三：病例库

#### 3.3.1 病例规模

- 急诊核心：20+个病例
- 内科：30+个病例
- 外科：20+个病例
- 其他专科：30+个病例
- 总计：100+个病例
- 每个病例分难度等级（⭐1-5）

#### 3.3.2 病例脚本结构

每个病例包含：
- 病人画像（人格组合）
- 主诉
- 现病史
- 既往史
- 关键病史点（评分点）
- 重点查体（评分点）
- 鉴别诊断
- 处置决策（评分点）
- 红旗症状
- 病情动态时间轴
- 易错点

#### 3.3.3 病例编辑工具

- Web端可视化编辑器
- 填表格式，不用写代码
- 写好后可以预览试对话效果
- 提交审核：老师写的病例要主任审核后才能上线

---

### 3.4 模块四：学习分析平台（对齐Osmosis）

#### 3.4.1 个人学习档案

- 能力雷达图：7维度当前水平
- 成长曲线：每个维度得分随时间变化（折线图）
- 薄弱点分析：哪几个维度最弱、进步最慢
- 训练统计：累计训练次数、累计时长、完成病例数
- 对标：跟同年级平均水平对比
- 结业考核预测：根据当前水平，预估结业考核通过率

#### 3.4.2 班级/机构分析

- 班级平均分
- 各维度平均分（7维度条形图）
- 薄弱点排名：全班哪个维度得分最低
- 学员进步趋势：最近一个月平均分变化
- 训练完成率：多少人完成了必做任务
- 按时间筛选（本周/本月/本季度）
- 多科室对比：哪个科室培训质量好

---

### 3.5 模块五：考试系统与题库（对齐Osmosis）

#### 3.5.1 模拟考核模式

- 全流程OSCE模拟考核
- 三考站：病史采集 + 体格检查 + 临床思维
- 全程计时，不能暂停
- 考完出成绩单
- 老师可以导出考核报告

#### 3.5.2 题库系统

- 按专科分类的练习题（1000+题）
- 每题有详细解析
- 错题本：自动收集做错的题
- 模拟考试：随机抽题组卷
- 结业考核模拟卷
- 高频考点标记

---

### 3.6 模块六：自适应学习引擎

- 学员某维度得分低 → 推荐该维度相关的病例
- 学员总是做错某类题 → 多推荐同类练习
- 学员进步快 → 自动提高病例难度
- 学员长期不练 → 推送提醒
- 个性化学习路径，不是所有人练一样的东西

---

### 3.7 模块七：老师端 · 教学管理

#### 3.7.1 学员管理

- 学员列表：姓名、科室、年级、最近训练时间、平均分
- 搜索学员、按科室/年级筛选
- 学员个人详情：训练记录、能力雷达图、薄弱点分析、老师评语

#### 3.7.2 评分复核

- 待复核列表：学员刚完成的训练
- 看对话记录 + AI评分明细
- 老师可以调整各维度得分、写评语
- 确认后学员看到最终评分

#### 3.7.3 任务布置

- 选择病例 → 选择学员/班级 → 设置截止时间
- 学员端显示"必做任务"
- 任务完成情况追踪

---

### 3.8 模块八：基地管理端

- 全院各科室平均分对比
- 培训进度追踪
- 数据导出（Excel/PDF）
- 迎检报表（按住培评估要求生成）
- 多院区数据汇总

## 四、非功能需求

### 4.1 性能要求

| 指标 | 要求 |
|------|------|
| 页面加载时间 | < 2秒 |
| AI对话响应时间 | < 3秒 |
| 评分计算时间 | < 5秒 |
| 并发支持 | 500人同时在线 |
| 系统可用性 | 99.5% |

### 4.2 安全与合规

| 要求 | 说明 |
|------|------|
| 等保三级 | 按医疗信息系统安全等级保护要求 |
| 数据本地化 | 数据存在国内阿里云，不出境 |
| 数据脱敏 | 学员数据匿名化，不存真实姓名（用学号） |
| 个保法 | 符合个人信息保护法 |
| 医疗器械 | 定位"医学教育"，不做诊疗辅助，不碰二类/三类医疗器械注册 |
