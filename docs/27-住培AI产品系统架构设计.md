# 住培AI产品 · 系统架构设计

> **设计时间：** 2026-10-19
> **设计理念：** 入口免费攥数据、数据中台做壁垒、企业侧变现赚钱——对标 OpenEvidence + Tempus，不是治趣的"卖软件"模式
> **铁律：** 不向医生/患者/医院科室收费；虚拟病人系统内不产生真实患者数据，天然合规

---

## 一、设计哲学：一句话讲清这个系统是什么

**这不是一个"OSCE训练软件"，而是一个"用AI问诊当采集器、把临床思维行为变成结构化数据资产、再卖给药企"的数据飞轮。**

```
学员用AI练问诊（免费，越用越爽）
        ↓
每次问诊都是一次标准化行为采集
        ↓
数据中台沉淀成"医生能力数据资产"
        ↓
脱敏后给药企：学术教育洞察 + MSL触达 + RWE
        ↓
药企付费 → 反哺基地免费/学员更好用 → 更多数据
```

**关键洞察：** 治趣把问诊日志当"成绩记录"扔掉了；我们把它当"石油"炼。这就是天花板差10倍的根本原因。

## 三、各层详细设计

### ① 基础设施层

| 组件 | 选型决策 | 理由 |
|------|---------|------|
| 云部署 | 国内阿里云/腾讯云；出海AWS | 国内合规+出海兼容 |
| 安全 | 等保三级 | 医疗教育系统准入门槛 |
| 多租户 | 行级隔离+租户ID | 每个住培基地独立数据空间 |
| 部署形态 | SaaS为主 + 私有化可选 | 先SaaS快速起量，标杆基地可私有化 |

**为什么：** 多租户SaaS是成本最低、起量最快的形态；私有化只给标杆基地（浙大系）做信任背书。

---

### ② 数据层（核心壁垒）——重点设计

这一层是整个系统的护城河，四个库各司其职：

| 数据库 | 内容 | 作用 |
|--------|------|------|
| **病例库** | OSCE考纲对齐的结构化病例脚本（主诉/现病史/查体/鉴别诊断） | 决定产品专业度 |
| **对话日志库** | 学员与AI虚拟病人的每一句对话（时序、内容、情绪） | **核心石油** |
| **评分库** | AI考官对每站的多维评分明细 | 能力量化 |
| **医生能力画像库** | 个体/基地/专科维度的能力雷达图 | 药企最想要的产品 |

**数据中台（关键）：**
```
原始对话日志
   ↓ 清洗/脱敏/标准化
结构化临床思维数据
   ↓ 按专科/地区/基地聚合
医生能力洞察产品（给药企）
```

**为什么这是壁垒：**
- 治趣有病例库但**没有把对话行为结构化**
- 你的数据越用越多、越用越准，后来者追不上
- 药企买的不是"软件"，是**脱敏的年轻医生临床决策偏差洞察**

---

### ③ AI能力层——四个引擎

**1. 医疗LLM网关（多模型路由）**
- **MVP期：** 接国产闭源API（DeepSeek/豆包）快速上线
- **成熟期：** 微调开源底座（HuatuoGPT-II）降本+私有化
- **设计：** 网关层抽象，可随时换模型，不绑死一家

**2. 语音引擎（ASR/TTS）**
- ASR：中文医疗语音识别（学员说话转文字）
- TTS：病人音色合成（不同人格/病情的声音）
- **MVP期：** 文字为主、语音为辅（降低复杂度）

**3. AI-VSP引擎（虚拟病人）**
- 病人人格模型（16种人格/情绪，对标思迈MedPersona）
- 病情逻辑引擎（问诊推进中病情动态变化）
- 动态应答（学员问什么，病人按病情逻辑答什么）

**4. OSCE评分引擎（最关键的差异化）**
```
规则引擎（OSCE评分表硬指标）
   + 模型评分（临床推理质量软指标）
   = 多维评分结果
```
- 病史采集完整性、查体合理性、鉴别诊断逻辑、医患沟通
- **设计：AI初评 + 带教老师抽检复核**（保留人的终审权，也是教学价值）

---

### ④ 业务应用层——四个端

| 端 | 用户 | 核心功能 |
|----|------|---------|
| **学员端** | 住培学员 | 选病例→AI问诊→即时评分→个人报告 |
| **考官/带教端** | 带教老师 | 审核病例、复核AI评分、布置训练 |
| **基地管理端** | 教学管理员 | 学员管理、通过率预测、基地间匿名对比 |
| **药企洞察端**（企业侧） | 药企医学部 | 脱敏病例训练洞察、MSL触达报告、RWE数据产品 |

**药企端是收入核心，不是附属功能：**
- 给药企看：某专科年轻医生在哪类病例上推理偏差最大
- 给药企看：哪个治疗领域的教学内容需求最高
- 数据全部脱敏、聚合，看不到个体学员

---

### ⑤ 接入层

- Web端（PC为主，学员在教室/宿舍用）
- 微信小程序（碎片化练习、提醒）
- 开放API（对接基地现有教务系统/成绩管理）

## 四、关键数据流（闭环）

```
学员登录 → 选病例 → 开始问诊（语音/文字）
   ↓
ASR识别 → LLM生成病人应答 → 实时记录对话流
   ↓
问诊结束 → 评分引擎（规则+模型）出分
   ↓
写入：对话日志库 + 评分库 + 能力画像库
   ↓
数据中台：脱敏 → 聚合 → 生成药企洞察产品
   ↓
药企付费 → 反哺基地免费/学员更好用
```

---

## 五、合规架构（为什么这个产品天然安全）

**核心优势：系统内全是虚拟病人，不接触真实患者数据。**

| 风险点 | 设计 |
|--------|------|
| 患者隐私 | 系统内是AI虚拟病人，**不产生真实患者数据**，天然规避《个保法》诊疗数据红线 |
| 学员数据 | 学员能力数据脱敏后才进入药企洞察端，看不到个人 |
| 数据出境 | 国内数据本地存储；出海用独立数据区 |
| 医疗AI监管 | 定位"医学教育"而非"诊疗辅助"，不碰医疗器械注册证红线 |

## 六、MVP切分（3个月，单基地试点）

| 维度 | MVP范围 |
|------|--------|
| 租户 | 单租户（树兰医院） |
| 专科 | 全科+内科，各20个病例 |
| 交互 | 文字问诊为主，语音为辅 |
| 评分 | 规则引擎+基础模型评分 |
| 端 | 学员端+考官端（管理端极简） |
| 药企端 | 暂不开放，先攒数据 |

**验证目标：** 学员愿意高频用 + 评分与带教老师人工评分一致性 >80%

## 八、为什么这个架构能跑通商业

1. **入口免费**：基地没理由拒绝（对比治趣要收费）
2. **数据飞轮**：越用数据越多，数据越多药企越想买
3. **企业侧付费**：药企学术教育50-200万/科/年 + RWE远期
4. **合规安全**：虚拟病人系统天然规避患者数据红线
5. **可复制**：同一套引擎，换考纲+语言即可出海
